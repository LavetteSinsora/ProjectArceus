Exploration = Q + bonus

exp_013 — reaching the first reward in a sparse world, as one clean idea.

The problem

No reward signal to chase — almost everywhere the reward is 0. We only care about how few environment steps until the first positive reward. So there's nothing to exploit yet; the whole game is shaping an intrinsic signal that gets us to a first success fastest.

The lens: every step is a bandit pull

At each state we choose an action under uncertainty — exactly the setting UCT/UCB was built for. Act on value plus an optimism term:

a* = argmaxa [  Q(s,a)  +  bonus(s,a)  ] UCB1: bonus = c·√( ln N(s) / N(s,a) ) — a confidence width on Q, shrinking like 1/√(visits)

What Q is — the backup, learned for free

Train a value head on the intrinsic reward by TD. It backs the discounted future novelty up into Q_int(s,a) = "expected future novelty if I go this way." That is the MCTS backup, amortized into a network — and acting on it is the tree policy. No tree to grow; the value function already carries it.

What the bonus is — RND, in its native form

The UCB bonus is fundamentally a width that shrinks as you visit (∝ 1/√N). RND prediction error is already exactly that — it falls as a region gets visited — so we use the error directly as the bonus, count-free. We do not try to reverse-engineer an integer count N̂ to plug into √(ln N/n).

Why no real counts? We measured it: on raw pixels, a state seen 1× and one seen 2000× land on the same error floor, and a never-seen state's error still dropped 99.9%. Maze frames are near-identical (one cell changes), so the random target is smooth and the predictor interpolates novelty everywhere. RND on pixels has no count resolution — so don't treat it as a count.

If we want real resolution: count in φ-space, then freeze

The inverse-dynamics encoder φ is trained to separate states that pixels conflate (it must, to predict the action between them). That de-smooths the manifold, so RND-on-φ regains resolution. Catch: φ keeps drifting (it never fully stabilizes), which moves the ruler. Fix: let φ separate (fast), then freeze it — resolution and a stationary ruler.

One scale, not three

Q, an RND error, and a kNN density live in different units — adding them means tuning weights while one swamps the others. So we don't hand-mix bonuses at decision time. Route novelty through the reward, let TD learn its scale, and act on Q_int. One channel, no scale-matching.

Won't it loop? — only if the policy is deterministic

A deterministic env does not force "go right, go left, repeat." That loop needs a deterministic policy. Keep the policy stochastic (entropy) and the same situation becomes a random walk that diffuses outward, with Q_int biasing it toward the unexplored. So the cheapest loop-breaker is the entropy we already have — no within-episode counter required.

Build it simplest-first

  1. RND-error-as-reward → Q_int, stochastic PPO. This is the UCT emulation (Q = backup, entropy = exploration, RND = optimism). Already in the harness; it solved LS20 L1. have it
  2. If the data shows within-episode looping wastes budget → a recurrent (GRU) policy: an implicit, learned episodic memory. No hashing, no kNN, no scale-mixing. only if needed
  3. Only then reach for explicit episodic memory (kNN-over-frozen-φ) or frontier-return (Go-Explore). heavy

Act on Q_int + RND-optimism. Push novelty through the reward channel so one value function learns the scale. Keep the policy stochastic so determinism becomes a random walk, not a loop. Add counts (in frozen controllable-φ) or memory only when measurement says we need them.
